# 2026 - October
## 1 - Thursday
### Small steps

   Took me some time to get the hang of using custom resources in Godot. Started implementing some stats and functions 
inside them, sketched some more ideas down, tested the results. Most of my time was spent on learning/testing code and 
syntax, and as I started to use more composition and custom resources I can see why they are OP in Godot, you can link 
so much stuff with them, and cleaner too, without the need of hard to understand code. The next task is to implement a
better speed system for the character using the stats I just made. Also after significant consideration, for now at

acces any input from anywhere in the game, it remains to be seen if it will be a problem down the road. Made some more 
changes to Godot Vim too, not everything is to my liking, it has some minor bugs, but I can live with them.
## 5 - Monday
### Thinking realy hard (*smells like fried brain cells*)

   I really like how resources work! Just made some advanced stat system for the player speed and stamina, there will be
a lot of adjustments to make, but it seems I'm on the right path implementing everything I have in mind. For the player
speed I want to be able to customize it (probably using the scroll wheel) and it also should be limited by the weight
you carry, to do it, made some min and max soft limits and the stat system handles the clamping of the value if it falls
out of range, there are some min and max hard limits too which make sure the soft limits remain inbound. You can query
the values in *meters/sec* or as *percentage*, both for the current value and the soft limits. I still have some tougths
about other logic needed there, but for now I'm happy how it's shaping up.

   Took me a lot of time just to think and understand how the systems will build up and what needs to go where. For
example there is still a `stats` node inside the player, which sounds logical to be there, but there is also a
`movement` component in the player which handles everything related to movement (obviously). For now, from the 4 stats,
*stamina* and *speed* must be handled by the `movement` component, the *weight* stat should be handled by some kind of
inventory system *(as a hack, there are two buttons assigned to increase/decrease the weight just to test stuff)*, and
the *strength* stat should be handled by ... something ... I don't know yet, but I'm not really sold on the idea that
the `stats` node will remain there.

## 7 - Wednesday

yet. At least now I know that while you define a variable in gdscript, the first thing is initializing all the variables
you declared but not with the values you declared for them, the first pass just declares them as their default 0, false
or empty strings, then on the second pass they get the values you assigned to them in the script. A refactor of the stat
system may be needed, not sure yet, but feels a tad complicated the way I did it, mostly because it's very hard to
follow even the debugger line by line, and I don't really understand all the set get methods that well.
